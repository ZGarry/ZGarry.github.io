连接器 × 蒸馏

从访问网页，到接入软件；从获取数据，到复用功能与工作流。原来，能力的边界还可以这样打开。

我的核心判断

反向代理等逆向技术，才是我们年轻人最应该掌握的技术。

本质就是一种连接器 + 蒸馏。

别人有的数据 → 我可以看
→ 我可以把它变成自己可用的数据

把“看到”继续做成读取、校验、保存和持续更新。在可访问、可保存的范围内，让数据真正进入自己的系统。

  1. 一个软件，大多数时候只用了其中一部分

    我需要的可能只是一份数据、一次计算或一个导出功能。找到最有用的那一段，就能把它接进自己的流程。

  2. 界面背后，还有 API、数据和工作流

    一个按钮背后，可能已经完成下载、整理、补缺、计算和导出。接入这个结果，也是在利用它之前完成的大量工作。

  3. 网页可以接，桌面软件也可以接

    网络请求、本地文件、缓存、数据库、SDK、命令行、进程通信，都可能是入口。界面只是其中一个接入位置。

  4. 逆向让入口可理解，连接器让入口可复用

    研究协议、文件格式和程序行为，弄清楚数据从哪里来、结果如何产生；再封装成输入明确、输出可验证的工具。反向代理负责转发流量，本身不等于逆向。

  5. 蒸馏：把别人已经会的，沉淀为自己的工具

    这里的蒸馏，是理解并吸收已有经验、功能与工作流，形成可复用的实现。可以先调用成熟软件，再根据价值决定是否独立实现。

  6. 能调用、能组合，也是一种能力

    一份文件、一个持续数据源、一个计算功能，各有价值。关键是知道自己获得了什么、仍依赖什么，以及能不能稳定重复使用。

  7. 新的能力，常常出现在连接器之间

    行情接公告，公告接持仓，持仓接研究与执行记录。多个软件各贡献一段，组合后可以回答任何单个软件都没有直接给出的问题。

  8. 接通一次之后，要能够长期使用

    记录来源、字段含义、更新时间和完整性；选定的数据按需留存、去重和更新。发现一次入口，积累一项可靠能力。

四条网页路线，继续向软件延伸

2026 年 9 月 20 日，《评估禅道接入 Stainless 方案》中讨论的四种访问方式。

01 · 正式 API
调用系统提供的接口；已有 OpenAPI 描述时，可以生成 SDK。
02 · JSON / GraphQL
理解网页背后的请求，把可以稳定复现的查询和操作封装起来。
03 · HTML / Form
直接请求页面、解析 HTML、提交表单，连接传统网站和企业后台。
04 · 浏览器自动化
操作页面元素，完成依赖浏览器环境的交互，必要时结合截图识别。

现在，再加上软件里的入口：本地文件与数据库、SDK 与命令行、私有协议与进程通信、运行时数据，以及桌面控件和视觉操作。按任务选择稳定、直接、容易验证的接入位置。

我到底接入了什么？

以行情软件为例，选择一种接入，看看自己获得的能力。

把已经整理好的数据接进来

例如读取本地历史行情或导出文件；具体内容与口径，需要对实际软件逐项核验。

本地文件 / 导出结果 → 解析与校验 → 自己可查询的数据

获得一份数据；接通持续更新后，才进一步获得长期数据源。

按自己的参数，调用它的计算

例如调用现有指标计算入口，让成熟软件对指定证券和日期返回结果。

我的参数 → 已有计算功能 → 核验结果 → 接入后续任务

获得可调用的功能；运行时仍可能依赖原软件、登录状态和数据源。

让它完成一段任务，再交给我

例如把已有的更新、补缺、整理与导出过程封装为一次任务，不必每次手工执行。

发起任务 → 更新与整理 → 导出与核验 → 我的系统继续处理

获得可编排的工作环节；记录完成状态，失败时能定位和恢复。
